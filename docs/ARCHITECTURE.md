# Tavriko — Verified Architecture Overview

## 1. Repository & Monorepo Layout
Tavriko is a TypeScript NPM-workspace monorepo (`package.json` workspaces: `shared`, `server`, `client`, `cloudflare`) with a Vercel serverless API adapter (`api/index.js`):

- [`shared/`](file:///c:/Users/%C3%96mer%20faruk%20%C5%9Fener/.gemini/antigravity/scratch/gmae/shared) (`@trivia/shared`): Shared domain contracts (`types.ts`), WebSocket/Socket.IO event constants (`events.ts`), authoritative scoring & ranking functions (`scoring.ts`), and static catalog/category definitions (`categories.ts`).
- [`client/`](file:///c:/Users/%C3%96mer%20faruk%20%C5%9Fener/.gemini/antigravity/scratch/gmae/client) (`@tavriko/client`): Expo 54 + React Native 0.81 + React 19 cross-platform client (iOS, Android, Web). Uses Zustand (`client/src/store/gameStore.ts`) for game state and custom state-driven screen navigation in [`RootNavigator.tsx`](file:///c:/Users/%C3%96mer%20faruk%20%C5%9Fener/.gemini/antigravity/scratch/gmae/client/src/navigation/RootNavigator.tsx).
- [`server/`](file:///c:/Users/%C3%96mer%20faruk%20%C5%9Fener/.gemini/antigravity/scratch/gmae/server) (`@tavriko/server`): Express 4 HTTP API, Prisma PostgreSQL persistence layer (`prismaClient.ts`), Supabase Auth/Storage sync (`supabaseClient.ts`), Upstash Redis cache/locks (`redisClient.ts`), AI question generator (`evrenLlmGenerator.ts`), Telegram review bot (`telegramBot.ts`), and local Socket.IO / `ws` fallback server (`server.ts`).
- [`cloudflare/`](file:///c:/Users/%C3%96mer%20faruk%20%C5%9Fener/.gemini/antigravity/scratch/gmae/cloudflare) (`@tavriko/realtime`): Production edge realtime gateway running on Cloudflare Workers + SQLite-backed Durable Objects (`GameRoomDO` and `MatchmakerDO`) using the WebSocket Hibernation API.
- [`api/index.js`](file:///c:/Users/%C3%96mer%20faruk%20%C5%9Fener/.gemini/antigravity/scratch/gmae/api/index.js): Vercel serverless entry point wrapping the compiled Express app (`server/dist/server.js`) and serving static web exports (`client/dist`).

## 2. Runtime Boundaries & End-to-End Data Flows

### A. Authentication & Profile Flow
1. **UI**: [`AuthScreen.tsx`](file:///c:/Users/%C3%96mer%20faruk%20%C5%9Fener/.gemini/antigravity/scratch/gmae/client/src/screens/AuthScreen.tsx) & [`RootNavigator.tsx`](file:///c:/Users/%C3%96mer%20faruk%20%C5%9Fener/.gemini/antigravity/scratch/gmae/client/src/navigation/RootNavigator.tsx) support Email/Username + Password login/registration, Google OAuth (via Supabase OAuth polling session `/api/auth/google/init-session` -> `/api/auth/google/complete-session`), and Guest play.
2. **API**: [`server/src/routes/authRoutes.ts`](file:///c:/Users/%C3%96mer%20faruk%20%C5%9Fener/.gemini/antigravity/scratch/gmae/server/src/routes/authRoutes.ts) validates credentials, hashes passwords (`bcryptjs`), issues JWTs (`jsonwebtoken`), and persists users via [`db` (`PrismaDatabaseService`)](file:///c:/Users/%C3%96mer%20faruk%20%C5%9Fener/.gemini/antigravity/scratch/gmae/server/src/db/prismaClient.ts).
3. **Persistence**: Primary user records live in Supabase PostgreSQL (`public.users` via Prisma), mirrored in memory (`this.users`) and synced to Supabase `profiles` / Storage (`supabaseClient.ts`).

### B. Single-Player (Practice / Explore / Daily Challenge) Flow
1. **UI -> API**: [`RootNavigator.tsx`](file:///c:/Users/%C3%96mer%20faruk%20%C5%9Fener/.gemini/antigravity/scratch/gmae/client/src/navigation/RootNavigator.tsx) (`handleStartPracticeInternal`) fetches questions from `GET /api/trivia/questions/practice` or `/api/trivia/questions/daily` ([`triviaRoutes.ts`](file:///c:/Users/%C3%96mer%20faruk%20%C5%9Fener/.gemini/antigravity/scratch/gmae/server/src/routes/triviaRoutes.ts)). `correctOptionId` is stripped before sending `ClientQuestion[]` to the client.
2. **Answer Validation**: When the player selects an option in [`QuizArenaScreen.tsx`](file:///c:/Users/%C3%96mer%20faruk%20%C5%9Fener/.gemini/antigravity/scratch/gmae/client/src/screens/QuizArenaScreen.tsx), the client posts `{ questionId, selectedOptionId, timeRemainingMs }` to `POST /api/trivia/questions/submit`.
3. **Anti-Cheat & Scoring**: [`triviaRoutes.ts`](file:///c:/Users/%C3%96mer%20faruk%20%C5%9Fener/.gemini/antigravity/scratch/gmae/server/src/routes/triviaRoutes.ts) acquires an idempotency lock via `cacheService.acquireAnswerLock`, verifies question expiry (`cacheService.getQuestionExpiry`), computes points via `calculateScore` (`shared/src/scoring.ts`), and returns `{ isCorrect, correctOptionId, explanation, pointsAwarded }`.
4. **UI Note**: In single-player mode, `activeRoom` is `null` and the multiplayer wave race bar (`BilBakalimWaveTrack`) is hidden.

### C. Multiplayer (1v1 Live Duel & Custom Friend Rooms) Flow
1. **Transport**: [`client/src/services/socketService.ts`](file:///c:/Users/%C3%96mer%20faruk%20%C5%9Fener/.gemini/antigravity/scratch/gmae/client/src/services/socketService.ts) connects via native WebSockets to the Cloudflare Worker (`wss://tavriko-realtime.uncertainidentity8.workers.dev`).
2. **Presence & Social Hub**: `/ws/presence` routes to the singleton `MatchmakerDO` (`global_matchmaker`), maintaining live online status (`presence:snapshot`, `presence:update`, `user:online`, `user:offline`) and relaying real-time social notifications (`social:notify` -> `notification:new`, `friends:update`).
3. **1v1 Matchmaking**: `/ws/matchmaking` routes to `MatchmakerDO`, which pairs two human players in queue or spawns a bot match after a 7-second alarm (`MATCH_TIMEOUT_MS = 7000`), initializing a dedicated `GameRoomDO` via `POST /create-match`.
4. **Authoritative Room Execution**: `/ws/room/:code` routes to a per-room `GameRoomDO` instance ([`cloudflare/src/durable-objects/GameRoom.ts`](file:///c:/Users/%C3%96mer%20faruk%20%C5%9Fener/.gemini/antigravity/scratch/gmae/cloudflare/src/durable-objects/GameRoom.ts)), which manages the state machine (`lobby` -> `countdown` -> `question` -> `round_result` -> `finished`), Durable Object alarms, server-side response timing, and race progression (`correctAnswersCount`).
